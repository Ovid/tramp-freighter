## Suggestions

- **[S1]** `src/game/state/managers/npc.js` (`requestLoan` ~460, `checkLoanDefaults` ~601), consumed at `src/features/station/StationMenu.jsx:34-35` and `src/features/repair/RepairPanel.jsx:38-39`. Both loan paths change `npcState.rep` and call only `markDirty()`; they never emit `NPCS_CHANGED`. The new subscriptions were added to keep tier displays current, so accepting a loan that crosses a tier (for example 55→60, Friendly→Trusted) leaves the badge and free-repair tier stale until something else re-renders. Fix: emit `NPCS_CHANGED` with `{ ...npcs }` after the rep change, as `modifyRepRaw` does. Confidence Medium. Found by Contract & Integration A and B and Concurrency & State B (`claude-opus-5-5`).
- **[S2]** `src/game/state/capabilities.js:297-319`. The `RepairCapabilities` typedef doesn't list the new `getNPCRep` and `getStoredNPCState`, and still says `getNPCState` is "for free repair checks". A mock built from the typedef makes `canGetFreeRepair` throw a TypeError. Fix: add both `@property` entries and narrow the `getNPCState` note to `applyFreeRepair`. Confidence High. Found by Contract & Integration A and B and Spec Compliance A (`claude-opus-5-5`).
- **[S3]** `src/game/state/game-coordinator.js:689-696`. `_emitAllStateEvents(migratedState)` runs before `checkAchievements()`, which can still throw. If it does:
  - when there is no previous state, subscribers keep the rejected save's values;
  - `ACHIEVEMENT_UNLOCKED` toasts that already fired stay on screen;
  - the `TIME_CHANGED` trigger has already run against the rejected save, and the rollback re-emit runs it again against the previous state, which can dispatch an encounter or narrative event.

  This is unlikely in practice. Fix: run `_registerEventEngine` and `checkAchievements` before emitting, so the catch only needs to restore `this.state`. Confidence Medium. Found by Logic & Correctness A and Concurrency & State A (`claude-opus-5-5`).
- **[S4]** `src/features/endgame/PostCreditsStation.jsx:12-24`. This sibling of `StationMenu` didn't get the same treatment. Its `useMemo` depends on a fresh `getNPCsAtSystem` array, so it recomputes every render, and it has no `NPCS_CHANGED` subscription. Staleness is theoretical, because no post-credits dialogue changes rep. Fix: mirror `StationMenu`. Confidence Medium. Found by Concurrency & State B and Spec Compliance B (`claude-opus-5-5`).
- **[S5]** `paad/architecture-reviews/2026-11-27-tramp-freighter-architecture-report.md:338-341`. The F-13 Status commit lists only `19f44d7` and leaves out `8edd047` and `6706b0c`. The reason doesn't mention `getStoredNPCState`, the `NPCS_CHANGED` subscriptions or the removed `useMemo`. Fix: list all three commits and extend the reason. Confidence High. Found by Spec Compliance A and B (`claude-opus-5-5`).
