## Important Issues

### [I1] Combat after a failed Flee rolls the same number again, so Evasive, Return Fire and Distress Call are certain to fail
- **File:** `src/game/state/managers/combat.js:28-33` (also `src/hooks/useEncounterOrchestration.js:75-100`, `:127-133`; `src/game/utils/seeded-random.js:94`)
- **Bug:** `resolveCombatChoice` seeds `new SeededRandom(buildEncounterSeed(daysElapsed, currentSystem, 'combat')).next()` on every call. Nothing between a failed Flee and the next combat choice changes the day or the system (a failed flee costs only hull), so the next choice gets the same random number. The failed flee already proved `rng >= evasive.finalChance` (≥ 0.6 + karma − strength). Return Fire (0.45 + …) and Distress Call (≤ 0.35 + …) are lower, so all three rolled options fail. Only Dump Cargo, which has no roll, can succeed, while the panel shows e.g. "45%". The specialist also flagged Flee from the negotiation panel, but the verifier corrected this: that path ends the encounter or uses a fresh seed, so it is unaffected.
- **Impact:** This breaks the F-3 contract the branch added to the `getCombatOdds` JSDoc ("what the player is shown is what the game uses") on the most common flee-then-fight path. It also makes Return Fire's harshest failure certain. The branch's new worn-engine evasion penalty (eea25c5) widens the failed-flee window, so more players land here.
- **Suggested fix:** Give each roll in an encounter its own random number: add an attempt counter or the choice name to the seed, or keep one `SeededRandom` per encounter and call `next()` for each roll. Add a test that Return Fire can succeed after a failed flee.
- **Confidence:** High
- **Found by:** Logic & Correctness A (`claude-opus-5-5`)

### Out-of-Scope Important

#### [OOSI1] lucky_ship quirk can never trigger — backlog id: `00e5fc32`
- **File:** `src/game/state/managers/combat.js:361-372`
- **Bug:** `checkLuckyShipNegate` reuses the random number that just failed the option's roll. A rescue needs `rng < 0.05 + 0.001·karma` (at most 0.15), but the roll already failed, so `rng >= finalChance`. The lowest possible `finalChance` is 0.25: Distress Call at +100 karma under escalation. So the quirk never fires. The odds breakdown also leaves it out.
- **Impact:** A ship quirk the player can see does nothing.
- **Suggested fix:** Give the lucky check its own random draw, then either list it in the odds breakdown or document that it is hidden.
- **Confidence:** Medium
- **Found by:** Logic & Correctness A (`claude-opus-5-5`)
- **Backlog status:** new

#### [OOSI2] Salvage ignores cargo space taken by passengers — backlog id: `ae66925e`
- **File:** `src/game/state/managers/outcome.js:159-162`
- **Bug:** `mergeSalvage` computes free space as `cargoCapacity − Σ cargo.qty`. `StateManager.getCargoRemaining()` also subtracts passenger `requirements.cargoSpace`. With passengers aboard, distress loot or a narrative `rewards.cargo` can overfill the hold, and `getCargoRemaining()` then goes negative. The branch moved this code unchanged from the deleted `applyEncounterOutcome.js`.
- **Impact:** The hold can end up over capacity, and trading then sees negative free space.
- **Suggested fix:** Pass a `getCargoRemaining` capability to OutcomeManager (add it to the typedef too) and use it as the starting free space. Consider reusing `TradingSystem.addCargoStack`.
- **Confidence:** Medium
- **Found by:** Contract & Integration B (`claude-opus-5-5`)
- **Backlog status:** new
