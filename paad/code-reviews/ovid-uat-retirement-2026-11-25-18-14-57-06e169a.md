## Important Issues

### [I1] Range Extender is stripped from the ship on every load
- **File:** `src/game/state/state-validators.js:728-734`
- **Bug:** `addStateDefaults` runs on every load (`game-coordinator.js:612`) and calls `validateShipConfigIds(state.ship.upgrades, SHIP_CONFIG.UPGRADES, 'upgrade')`. Commit 3013096 deliberately put `range_extender` in the separate `SHIP_CONFIG.QUEST_UPGRADES` map. The validator only checks `UPGRADES`, so it logs "Unknown upgrade ID: range_extender" and removes the upgrade. Separately, `calculateShipCapabilities` (`ship.js:510-513`) also reads only `SHIP_CONFIG.UPGRADES` and warns "Unknown upgrade installed: range_extender" on jump validation and refuel paths.
- **Impact:** The Ship Status fix in `getUpgradeDefinition` (`ship.js:169-175`) only works until the next reload. After that, the one-shot quest reward is silently gone from save data. Any `upgrades.includes('range_extender')` check also fails. The new unit test calls `getUpgradeDefinition` directly, so it never exercises the load path.
- **Suggested fix:** Validate against `{ ...SHIP_CONFIG.UPGRADES, ...SHIP_CONFIG.QUEST_UPGRADES }`. Have `calculateShipCapabilities` use `getUpgradeDefinition`. Add a save/load round-trip test that keeps `range_extender`.
- **Confidence:** High
- **Found by:** Contract & Integration, Error Handling & Edge Cases (`claude-opus-5-5`)

### [I2] Once-per-choice repGain also caps repeatable paid loan choices
- **File:** `src/game/game-dialogue.js:327-335` (applied at :394)
- **Bug:** `shouldAwardRepGain` exempts only `repGain < 0` and `picker` choices. Choices with an `action` are not exempt. The loan choices `request_loan` (+3, `context.requestLoan()`) and `repay_loan` (+2, `context.repayLoan()`) appear in seven NPC trees (captain-vasquez, dr-sarah-kim, lucky-liu, rusty-rodriguez, station-master-kowalski, whisper, zara-osman). These loans repeat: `npc.js:504-505` resets `loanAmount` and `canRequestFavor` applies only a cooldown. From the second cycle on, they pay 0 dialogue rep. The claim is also recorded even when the action returns `{success:false}`, because `selectChoice` only warns on failure. So a failed first repayment uses up the claim permanently.
- **Impact:** Players pay real credits and get no reputation. This contradicts the test header at `tests/unit/dialogue-rep-once.test.js:2-4`: "Choices with a real cost (actions, cargo pickers) are unaffected." No test covers action choices.
- **Suggested fix:** Add `|| typeof choice.action === 'function'` to the exemption. Skip both the award and the claim when the action result has `success === false`. Add a test that runs a loan request→repay→request cycle.
- **Confidence:** High
- **Found by:** Logic & Correctness, Concurrency & State, Contract & Integration, Spec Compliance (`claude-opus-5-5`)
