## Important Issues

### [I1] Build and test configs crash at load when git or `.git` is missing
- **File:** `shared-config.js:8-17`
- **Bug:** `appVersion()` runs at module load (through `define`, line 15). It calls `execSync('git rev-list --count HEAD')` and `readFileSync('package.json')` (resolved from the working directory), and neither call has a try/catch. Both `vite.config.js:3` and `vitest.config.js:3` import `define`.
- **Impact:** in a ZIP or tarball export, a container build context without `.git`, a machine with no git, or a repo where git refuses with "dubious ownership", `execSync` throws and the config never loads. `npm run build`, `npm run dev`, `vite preview`, `npm test` and the Makefile build/deploy targets all abort, because of a cosmetic version string. On main, the configs had no git dependency.
- **Suggested fix:** wrap the git call in try/catch and fall back to a patch value such as `0` or `dev` (the title-screen property test's `[1-9]\d*` regex would have to accept it). Optionally pass `stdio: ['ignore','pipe','ignore']`. Reading package.json via `new URL('./package.json', import.meta.url)` is a minor extra hardening.
- **Confidence:** Medium
- **Found by:** Logic & Correctness, Error Handling, Contract & Integration, Spec Compliance, Concurrency & State (`claude-opus-5-5`)

### [I2] `canAffordStandardRepair` doesn't match the standard repairs the panel offers
- **File:** `src/game/state/managers/repair.js:170-178` (used at `repair.js:208` in `applyEmergencyPatch` and at `src/features/repair/RepairPanel.jsx:321-335` for whether the patch section shows)
- **Bug:** the check prices exactly `EMERGENCY_PATCH_TARGET - condition` points (at most 21 points, ₡5–₡105). The panel's buttons only offer `UI_CONFIG.REPAIR_AMOUNTS = [10, 25, 50, 'full']`, so the cheapest one costs ₡50 or more. The check also ignores the repair NPC discount that the buttons apply.
- **Impact:** take a system at 12–20% with credits in `[5*(21-condition), 50)`. The check returns true, so the Emergency Patch section is hidden and `applyEmergencyPatch` refuses with "You can afford standard repair". Every standard button is still disabled for lack of credits. A broke player with a critical system can neither patch nor repair, and that is the exact case the patch exists for. The formula is inherited from the old `canAffordRepairAboveThreshold`. This branch made it the single shared rule for both the UI and the manager guard. The F-6 fix aimed at the button showing exactly what is charged, and this rule still doesn't match what the buttons show.
- **Suggested fix:** base affordability on the cheapest standard repair actually offered that reaches the target, at the player's best discount. That is the smallest `REPAIR_AMOUNTS` entry ≥ `needed`, or Full, priced with `getRepairCost(sys, amount, cond, discount)`. Note that `Math.max(needed, smallestOfferedAmount)` is wrong when `needed` falls between offered amounts. Conditions can be fractional (life support drops 0.5 per day). Alternatively, offer a standard repair of exactly `needed` points. A RepairPanel test with hull=20 and credits=30 would confirm the bug.
- **Confidence:** Medium
- **Found by:** Logic & Correctness, Spec Compliance (`claude-opus-5-5`)
